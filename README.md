## 先看单核主频，再看核心数

Minecraft 的主世界 tick 计算基本压在单个核心上。你给它 8 核，它也只把其中一个跑满。TPS（每秒游戏刻）掉下去的时候，玩家看到的是方块挖了不掉、怪物原地卡住、走路被拉回原位，这些现象跟“核心数够不够”关系不大，跟“那一个核心跑多快”关系很大。

这一点在几份教程里口径一致。1.21 多服务端开服教程写得很直接：“服务器配置建议 4 核 8G 以上，最低不要低于 4 核 8G，而且服务器 CPU 要那种高主频高单核性能的，比如 14900K/13900K、5900X 之类的，高版本的 java 服很吃单核性能和内存。”腾讯云那篇一站式部署实录也提到，Minecraft 对单核主频敏感，普通型实例可能稍卡，建议开高性能实例或手动优化。

所以“4 核 8G”这个说法本身不够，同样标 4 核 8G 的两台机器，一台是 6.0GHz 的桌面级处理器，一台是低频服务器 U，开 1.21 加十几个模组，体验差一个档。筛选机型时把 CPU 型号也当成必看项。

## 人数对应配置

| 人数 / 玩法 | CPU | 内存 | 带宽 | 依据 |
| --- | --- | --- | --- | --- |
| 2–3 人，原版或轻量插件 | 2 核，主频别太低 | 4G，堆内存给 3G 左右 | 5Mbps 起 | 轻量场景的最低线；只内网玩可低，外网联机要更高 |
| 5–10 人，Paper 插件服 | 4 核，高主频 | 8G | 10Mbps 起 | 4 核 8G 可支持 10–15 名玩家同时在线的口径 |
| 10 人以上，或带模组整合包 | 4 核起，优先高主频 | 8G 起，按整合包加 | 10Mbps 以上 | 1.21 高版本 + 面板 + 多实例的保守下限 |

带宽这条容易被忽略。原版端一个玩家大概吃 1.5Mbps 左右，听着不多，但同时在线人数一多、区块加载一密集，上行不够就是集体卡顿。5Mbps 只适合小服或内网，外网联机 10Mbps 起步更稳。

## 服务端怎么选

| 服务端 | 是什么 | 适合谁 |
| --- | --- | --- |
| 原版 | 官方服务端，无修改 | 纯净生存，不加模组不加插件 |
| Paper | Spigot 的高性能分支，兼容大部分 Bukkit/Spigot 插件 | 要性能和稳定性，开插件服 |
| Fabric | 更轻量、更新更快 | 追最新版本，装 Fabric 模组 |
| Forge | 使用最广的模组加载器和 API | 大型模组整合包 |
| Mohist | 融合 Forge 与 Bukkit/Spigot，模组和插件同时跑 | 既要模组又要插件 |

选 Fabric 还是 Forge 有个实用判断：整合包作者发的是哪种就用哪种，别自己换。2024 年那份 1.21 教程里，Mohist 当时只更新到 1.20.2，版本明显滞后，现在要开 1.21 得先去官网确认有没有对应构建，别照着两年前的教程下包。

模组这块有一条规则，多数教程一句带过，但踩了会很浪费时间：原版 `server.jar` 不能加模组，必须换 Fabric 或 Forge 端；模组分服务端模组和客户端模组，连锁采集这类服务端模组要求本地和服务器版本完全一致，小地图这类客户端模组只装本地就行；Fabric 端还必须把 Fabric-API 放进 `mods` 文件夹，否则其他模组全部不生效。

## 四条开服路线，按你的动手意愿挑

**路线 A：手动 + 启动脚本。** 装 JDK，下载服务端 jar，写一个 `start.sh`，内容是 `java -Xmx7G -Xms7G -jar paper.jar nogui`。适合想把每一步都搞明白的人。坑在第一次启动：服务端会生成 `eula.txt`，`eula=false` 必须改成 `true`，否则直接退出。

**路线 B：Docker Compose。** 用 `itzg/minecraft-server` 镜像，`EULA`、`VERSION`、`MEMORY`、`SERVER_PORT` 全走环境变量。适合一台机器上还要跑别的服务、想用容器隔离的人。坑有两个：首次启动生成完世界会自己停一次，得 `docker compose restart` 再起；Docker 默认限制内存，机器只有 2G 还同时跑容器和 MC，很容易 OOM，要在 compose 里写 `deploy.resources.limits.memory`。

**路线 C：MCSManager 面板。** 一键脚本装完自动启动并开机自启，服务名是 `mcsm-daemon.service` 和 `mcsm-web.service`，浏览器访问 `http://IP:23333/` 就能管。面板里文件管理、配置文件、事件任务、实例设置都是图形化的，换存档、传模组在网页上点几下就完。适合不想碰命令行的人。坑是端口：面板要 23333，节点 daemon 要 24444，两个都得在安全组放行，只开 23333 会看到面板但实例起不来。

雨云的游戏云本身就分面板型和 VPS 型两种形态：面板型在网页上选服务端类型、开机、配 NAT 端口映射，不用自己装环境；VPS 型给完整系统权限，能开多服、挂群组。第一次开服、只想快点跟朋友进游戏，面板型省事得多。

**路线 D：systemd 全托管。** GitHub 上有个零依赖方案，把 `install.sh` 贴进云厂商的 User Data，开机自动装依赖、写 `server.properties`、装 `systemd/minecraft.service`。服务跑在无登录 shell 的 `minecraft` 系统用户下，崩溃自动重启、开机自启，配一个 `mc-wizard` 命令行做启停、看日志、发指令、快照世界。要求 Ubuntu 24.04，Java 版和基岩版都建议 8G 内存，`JAVA_MEMORY` 默认 2G。

这四条路线的实际差别在进程托管：`screen` 或 `nohup` 起服，SSH 一断、进程一崩就没了，得手动拉起来；systemd 能在崩溃和重启后自动恢复；面板则把启停、日志、文件管理都搬到网页上，代价是多占两个端口和一部分内存。

## 端口与安全组

| 用途 | 端口 | 协议 |
| --- | --- | --- |
| Minecraft Java | 25565 | TCP |
| Minecraft 基岩版 | 19132 | UDP |
| SSH | 22 | TCP |
| MCSManager 面板 | 23333 | TCP |
| MCSManager 节点 daemon | 24444 | TCP |

只放行你要用的，其他一律关掉。有的教程直接 `systemctl stop firewalld` 关掉整台机器的防火墙，同一位作者也补了一句“也可以不关闭防火墙，只需配置开放所需要的端口即可，这样更安全”。后者才是该照做的做法。

用域名加 HTTPS 的话，A 记录要先解析到服务器 IP，再去申请 Let's Encrypt 证书，域名没解析就申请必然失败。同一台机器上如果还跑网盘之类的服务，端口记得错开，Alist 常用 5240、Cloudreve 常用 52917，都和 25565 不冲突才行。

## 五个必踩的坑

**EULA 没同意。** 启动报 `You need to agree to the EULA in order to run the server`。打开 `eula.txt` 把 `false` 改成 `true`。

**内存溢出。** 容器或面板环境下 JVM 会以为自己能用满整机内存，实际被 cgroup 卡住就 OOM。容器场景用 `-XX:MaxRAMPercentage=95.0` 这类百分比写法，让 JVM 按实际可用内存算；裸机用 `-Xmx4G -Xms4G` 固定值也行，两种都别超过机器物理内存。

**换存档后起不来。** 用非 root 用户（比如 `mcfabricuser`）跑服，换完 `world` 文件夹要重新赋权：`sudo chown -R mcfabricuser:mcfabricuser /minecraft`。不做这一步，服务端读得到文件但写不进去，启动直接失败。

**Java 版本对不上。** 1.19 配 JDK 17，1.21 配 JDK 21。教程里写 `openjdk-17` 的那篇示例版本是 1.19，照抄到 1.21 上会起不来。装完用 `java -version` 确认。

**CentOS 7 装不上面板。** 安装 MCSManager 会提示操作系统版本过低。新装机器直接用 Ubuntu 24.04 LTS 或 22.04 LTS，CentOS 8 以上也可以。只用命令行不开面板的话，CentOS 7 还能凑合。

## 换周目、升级服务端，该保留哪些文件

这一步前排教程基本没讲，但换端之后发现 OP 没了、白名单空了、封禁名单重置，原因都在这里。

整合包作者给出的升级步骤是：先关旧服，然后**除了下面这些，其他全部删除**——`world` 文件夹、`banned-ips.json`、`banned-players.json`、`ops.json`、`server_banlist_config.json`、`server.properties`、`usercache.json`、`usernamecache.json`、`whitelist.json`。面板服不要删启动脚本。之后上传新服务端压缩包解压，把启动脚本指到新 jar 上。

反过来读这份清单就明白了：管理员身份在 `ops.json`，白名单在 `whitelist.json`，封禁记录在两个 `banned-*.json` 里，玩家 UUID 缓存对应 `usercache.json` 和 `usernamecache.json`。这些文件不带着走，换完端就是一座空城。

如果走的是 systemd 那套方案，换图有更省事的做法：`mc-wizard save` 在不停服的情况下快照当前世界，Java 端会先执行 `save-all` 把数据刷到磁盘；`mc-wizard swap <world>` 切换世界时，会把当前活跃世界自动移回 `/opt/minecraft/worlds/`，不会丢。手动方案则要记牢：上传存档、`rm -rf world/`、`mv 存档名/ world`，文件夹名必须和 `world` 完全一致。

## 最后怎么定

2 到 3 人、偶尔周末上线，2 核 4G 够用，把堆内存压到 3G 左右，别在同一台机器上再开面板和网盘。5 到 10 人的插件服，4 核 8G 加高主频，这是最省心的一档。10 人以上、或者上大型模组整合包，8G 只是起点，内存和主频都要往上加，有条件的话把服务和别的应用拆到不同机器。
